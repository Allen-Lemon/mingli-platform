### 技术选型
- 后端：Java 8 + Spring Boot 2.7.18 + MyBatis 2.3.2 + MySQL 8（另加 H2 作为免安装演示 profile）
- 前端：Vue 3 + Vite 5 + Element Plus，端口 5173，proxy /api → 8080

### 核心实现
- `LunarCalendar`：儒略日换算；Meeus 太阳视黄经迭代求 24 节气（含章动 Δψ、光行差、ΔT 分段多项式）；
  真太阳时（经度 4 分钟/度 + 时差 EOT）
- `BaziPaiPan`：五虎遁 / 五鼠遁 / 日干支 `(JDN+49) mod 60`（以 2024-02-10 甲辰日为锚点反推）/ 夜子时顺延 /
  藏干 / 纳音 / 空亡 / 起运大运
- `MingLiRuleEngine`：10 个分析分块，输出规则命中并带原文编号（1.1…7.2），存疑项打 doubtful 标记
- `DictService`：`dict_*` 表经 MyBatis 加载并缓存，失败回退内置默认（保证无 DB 也能排盘）

### 关键坑（重要）
1. **节气精度**：Meeus 截断级数与《中国天文年历》差约 −7 分钟（实测 2024 立春 16:22 vs 16:27，
   2026 立春 03:52 vs 04:01），误差上限约 ±15 分钟 = 0.01°。**未能**通过加章动/ΔT 消除（只改善约 1 分钟）。
   对策：距「节」不足 30 分钟时输出 `boundaryWarning` 并给出两套年/月柱供复核。
2. **H2 跨表同名索引冲突**：`UNIQUE KEY uk_gan` 在两张表重复 → H2 下第二张表创建失败。
   所有索引名必须加表名前缀（MySQL 下同名合法，容易漏）。
3. **spring.sql.init 与 @PostConstruct 竞态**：MyBatis 字典加载早于建表脚本执行完。
   改为 `ensureDbLoaded()` 懒加载 + 10 秒冷却重试。
4. **枚举 JSON 序列化**：`TianGan` / `DiZhi` 直接作为字段会被 Jackson 序列化成 `XIN`。
   在 `getCn()` 上加 `@JsonValue` 解决。
5. 本机 `mvn` 在 Git Bash 下报「找不到主类 classworlds」，须用
   `java -classpath <maven>/boot/plexus-classworlds-*.jar -Dclassworlds.conf=... org.codehaus...Launcher` 调用。
6. 并行 Edit 同一文件会互相覆盖 —— 同一文件的多处修改必须串行，或整文件重写。

### 当晚追加：dict 三表为空的根因与修复（关键）
- 现象：`/api/dict/all` 返回 `lushen=0 / ganWuxiang=0 / zhiWuxiang=0`，其余 9 表正常，source=MySQL。
- 排查：用 `h2-2.1.214.jar` 单独跑 schema.sql+data.sql（同 H2 设置）三表都正常 → 排除 SQL 本身；
  最终靠 `org.springframework.jdbc.datasource.init.ScriptUtils` 的 DEBUG 日志定位到
  `Unique index violation ... U&'\6d93\fffd'`，`\fffd` 即 Unicode 替换符 → **中文被读成乱码**。
- 根因：Windows 下 `spring.sql.init` 默认用平台编码(GBK) 读取 UTF-8 的脚本，中文天干/地支变乱码后
  唯一键冲突，整条 INSERT 被丢弃。
- 修复：`application.yml` 显式加 `spring.sql.init.encoding: UTF-8`；并补
  `DictService` 的 `ApplicationReadyEvent` 监听，在 sql.init 全部完成后重载字典（防竞态）。
- 验证：重启后 `/api/dict/all` 三表恢复为 10/10/12，中文内容正确（禄神 甲→寅 等）；
  排盘 1990-05-20 午时 = 庚午 辛巳 乙酉 壬午、1988-03-15 巳时 = 戊辰 乙卯 己巳 己巳，四柱准确。
- 清理：删除临时 `Repro.java`、`h2test/`、`DebugController`。

### 续（Docker Compose 部署化）
- 用户需求：把项目做成可部署到服务器的 docker compose 镜像。产出 6 个文件：
  - `mingli-backend/Dockerfile`（多阶段 maven:3.9-eclipse-temurin-8 → eclipse-temurin:8-jre；ENTRYPOINT 带 `-Xmx512m -Xms128m`）、`mingli-backend/.dockerignore`
  - `mingli-web/Dockerfile`（node:20-alpine 构建 dist → nginx:alpine 托管）、`mingli-web/.dockerignore`、`mingli-web/nginx.conf`
  - 根 `docker-compose.yml`（mysql:8.0 + backend + frontend 三服务）、`.env.example`、`README.docker.md`
- 关键设计（避免踩坑）：
  1. **nginx 反向代理 `/api` 不能剥离前缀**：后端 `@RequestMapping("/api/dict")`/`("/api/bazi")`，故 `proxy_pass http://backend:8080;`（结尾无 `/`）。若误加 `/` 会把 `/api` 前缀剥掉导致全部 404。
  2. **MySQL 自动建库**：`MYSQL_DATABASE=mingli` 让容器首启即建库，后端 `schema.sql`（`CREATE DATABASE IF NOT EXISTS`+`USE`）为幂等 no-op；`data.sql` 只动 dict_*，历史表 `bazi_record` 重启不清空。
  3. **密码一致**：`MYSQL_ROOT_PASSWORD` 经 compose 变量同时注入 MySQL 与 `SPRING_DATASOURCE_PASSWORD`（均 `${MYSQL_ROOT_PASSWORD:-root}`），避免两处不一致连不上库。
  4. **启动顺序**：backend `depends_on: mysql: condition: service_healthy`；mysql healthcheck 用 `mysqladmin ping`，`$$` 转义防止被宿主机提前展开。
  5. **堆内存**：复用 `-Xmx512m -Xms128m`，防云主机内存受限时 JVM 默认 ~4GB 启动失败。
- 沙箱无 Docker，无法 build/test，已用 PyYAML 校验 compose 结构与 nginx proxy_pass，逻辑正确。
